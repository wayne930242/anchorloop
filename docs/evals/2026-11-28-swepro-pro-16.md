# Anchorloop on 16 SWE-Bench Pro tasks

On these tasks, the agent stated a check before editing and showed a passing result after the last edit in 42% of trials with anchorloop and 6% without it.
The task verifier passed 22 of 48 trials with anchorloop (46%) and 14 of 48 without it (29%), but the 95% confidence interval for that difference includes zero.

## Setup

An initial screen of 40 SWE-Bench Pro tasks prioritized tasks that sometimes passed, followed by tasks that came closest to passing.
The A/B run (`swepro-luna-ab`) used 16 of those tasks, with three new trials per task in each arm (`k=3`), for 96 valid trials and no retries.
Both arms used `openai-codex/gpt-6-luna` at medium reasoning effort in pi 1.6.1; the bare arm did not load anchorloop, and the other arm did.
Neither arm launched subagents.
The runner estimated a total cost of US$1.12; this is a USD equivalent, not a bill.

## Metrics

A trial passed if it passed the task's verifier.
`pass@1` is the mean single-trial pass rate across tasks, and `pass^3` is the share of tasks that passed all three trials.
For the combined process metric, the runner looked for both a check stated before the first edit and evidence of a passing check after the last edit.
The figures come from `exp show swepro-luna-ab`, which pairs the two arms by task and uses bootstrap resampling to estimate the confidence intervals.
The runner rounds each rate, difference, and cost separately, so differences and totals may not match arithmetic on the displayed values.
A dash means the runner did not report a value, and pp means percentage points.

## Limits

The run covered only 16 screened tasks and one model at one reasoning setting, so the rates do not estimate performance across SWE-Bench Pro or other models.
The pass-rate difference has a 95% confidence interval of −4 to +38 percentage points, so the run does not establish a pass-rate improvement.
