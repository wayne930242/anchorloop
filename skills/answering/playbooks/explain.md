# Explain

**You own the user's understanding.**

1. Name the one mechanism or outcome the user needs and lead with it. Infer from the conversation why they ask (change, review, debug, learn) and put the depth there; give a concept new to them one general-definition sentence before this repo's case.
2. For a change or result, start from what the user or the next maintainer will notice, then the cause; describe the change instead of showing a diff.
3. Cut every section that does not move the user toward that point.
4. When the user says they did not follow, restate your last reply shorter, in words a colleague would say aloud, with no new claims; name each coined term once or drop it.

**Reply:** the point in a line or two, then the supporting views with sources.
