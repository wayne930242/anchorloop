# Bug fix

**You own the root cause.** Every shipped line traces to runtime evidence ([**Fix root causes**](../../anchorloop/principles/fix-root-causes.md)).

1. Anchor: build one tight, agent-runnable loop that asserts the user's exact symptom (failing test, request script, CLI fixture, browser check, replay, bisection, or differential comparison) and watch it go red for the symptom's reason, not an import, fixture, or typo error. For flaky behavior, raise and measure the reproduction rate. Minimize it until every element is load-bearing. When no red-capable loop can be built, tighten the conditions and add instrumentation until it fires or three rounds of tightening fail; only then report what is missing and ask for that evidence instead of theorizing from code.
2. Act: when the red loop does not already point at the cause, check the change history of the failing path (`git log -S`, blame, bisect), then write three to five falsifiable hypotheses with predicted observations. Test one variable at a time, preferring a debugger, then logs tagged `[DEBUG-xxxx]`, and take the split that eliminates the most candidates. Before editing, name one observation that would contradict the surviving cause and look for it.
3. Act: when two fixes resting on one premise fail the same loop, apply [**Attack the premise**](../../anchorloop/principles/attack-the-premise.md) before a third. A contradicted premise sends you back to the hypotheses; a confirmed one means the fixes treated a consequence, so ask the next why.
4. Act: an architectural cause returns to Classify as Durable. Otherwise turn the minimized repro into a regression test at the public seam ([**Test behavior, not implementation**](../../anchorloop/principles/test-behavior-not-implementation.md)), committed failing before the fix when that is cheap ([**Sequence verifiable units**](../../anchorloop/principles/sequence-verifiable-units.md)), and make the smallest change that turns it green. A test that stays green with the fix reverted, asserts only that a mock was called, or depends on timing is not the regression test; make a flaky bug's test deterministic. A change the evidence did not motivate is reverted.
5. Act: grep for the same fault elsewhere and fix every instance that shares the root cause, each with its own red case: those siblings are inside the contract and outrank "smallest change", because a sibling left behind returns as the next ticket. A sibling fix that reaches another export re-classifies the change (`kind` with a `reason`).
6. Verify: run the regression test and the affected suite on the surface the user saw, then remove every `[DEBUG-xxxx]` probe and throwaway artifact.

**Reply:** what was broken, the root cause, the fix, and the failing-then-passing output; when the deciding fact took a deep dig, the always-on signal that would have shown it at first look, listed as a follow-up.
