# Feature

**You own the design.**

1. Align: learn how the affected subsystem works now by reading every file the change touches, and name the data shape and its organizing structure ([**Model the domain**](../../anchorloop/principles/model-the-domain.md), [**Foundational thinking**](../../anchorloop/principles/foundational-thinking.md), [**Type system discipline**](../../anchorloop/principles/type-system-discipline.md)) before any logic. Do what every later phase leans on first, such as test infrastructure and shared types.
2. Act: when the change crosses a module, settle its interface first. Write two or three real call sites and derive the signatures from them. Place the seam at an existing boundary; add one only for real variation, because one adapter is hypothetical and two demonstrate variation. Hide invariants and ordering behind the interface, make it the test surface, and guard only where untrusted input enters ([**Boundary discipline**](../../anchorloop/principles/boundary-discipline.md)). A module whose removal makes complexity vanish rather than move to callers is a pass-through; delete it. Screen the shape against [design-red-flags](../references/design-red-flags.md). With no precedent and a costly-to-reverse choice, compare two interface shapes on depth, locality, compatibility, and testability, or settle it with the `prototype` playbook; a user-owned trade-off goes to the user.
3. Act: for state that runs, give each actor its own state and merge at the read boundary; a lock added by reflex means the state was shared by mistake ([**Separate before serializing shared state**](../../anchorloop/principles/separate-before-serializing-shared-state.md)). For an operation that mutates state, ask what happens when it runs twice or crashes halfway ([**Make operations idempotent**](../../anchorloop/principles/make-operations-idempotent.md)).
4. Act: the settled interface is a signal, not an obstacle. Surface each deviation from it, and when the same workaround appears a second time, return to Align and reshape as if the constraints were there from day one, deleting before adding.
5. Act: when dispatching parallel workers, write the throughput checkpoint as four `todo` items, each `n/a: <reason>` when it does not apply: blocking first steps; independent workstreams; shared mutable state, split before serializing; the smallest safe decomposition. Work that is coupled in code (one feature, one migration) goes to a single owner; fan out only slices that produce independent artifacts. Bulk jobs follow [**Build the lever**](../../anchorloop/principles/build-the-lever.md). For three or more near-identical units, run one through brief, report, and check before launching the rest, so a flaw in the brief costs one worker.
6. Act: build in units that each end in a check, each commit passing alone ([**Sequence verifiable units**](../../anchorloop/principles/sequence-verifiable-units.md)). A shared primitive's improvement is ported to every consumer and verified on each.
7. Verify: on the surface the user will use; an inconclusive or wrong-surface result is not a pass.

**Reply:** what was built, the shape chosen and why, the checkpoint, and open decisions; a table when alternatives were compared.
